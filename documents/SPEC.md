# 『100分 de 名著』読書ルーレット 仕様書

- 文書バージョン：1.0
- 作成日：2026-10-16
- 対象：GitHub Copilotによる実装
- 公開先：GitHub Pages
- アプリ形態：静的Webアプリ
- 開発方針：小さく作り、個人で使える品質を確保してから公開する

## 1. 概要

### 1.1 目的

NHK『100分 de 名著』シリーズの書籍カタログから、まだ読んでいない本をルーレットで選び、読書のきっかけを作るWebアプリを開発する。

本の手動登録を主目的としない。あらかじめ用意されたカタログの中で、読んだことのある本に読書状況を設定し、それらを抽選対象から除外できるようにする。

### 1.2 基本方針

- 誰でも利用できる公開Webアプリとする。
- ログイン機能は実装しない。
- 利用者の読書記録はブラウザ内に保存する。
- サーバー、独自バックエンド、データベースを必要としない。
- 書籍カタログは利用者の読書記録とは独立して更新できる。
- アフィリエイト機能は実装しない。
- スマートフォンでの利用を優先する。

## 2. 対象範囲

### 2.1 書籍カタログ

次の3種類をすべて対象とする。

1. テキスト：番組の月刊テキスト
2. ブックス：『100分 de 名著ブックス』シリーズ
3. 別冊：『100分 de 名著』関連の別冊・特別企画書籍

NHK出版の公式サイトを第一候補のデータソースとする。公開書誌APIなどの補助利用も検討する。

重要事項：
- 取得元のHTML構造、APIの利用条件、取得可能な書籍の範囲を実装前に検証する。
- 公開APIが存在すると仮定して実装しない。
- 取得方法はデータ取得モジュールに閉じ込め、画面から分離する。
- 公式サイトからの自動取得が利用条件上または技術上困難な場合に備え、正規化済みJSONの生成・補正ができる構成にする。
- 3種類のカタログを取得できているかを検証し、取得漏れを黙って成功扱いしない。
- 書籍情報や書影の利用条件を確認する。

### 2.2 MVPに含める機能

- 書籍一覧の表示
- 書籍の検索
- 種類別フィルター
- 読書状況の変更
- 未読書籍のルーレット抽選
- 書影サムネイルの表示
- 公式商品ページへのリンク
- 読書記録の自動保存
- JSON形式でのバックアップ・復元
- GitHub Pagesへの自動デプロイ

### 2.3 MVPでは実装しない機能

- ユーザー登録・ログイン
- 複数端末間の同期
- 書籍の手動登録
- SNS共有、ランキング、レビュー
- Amazonアフィリエイト
- 読書目標・連続読書日数・通知
- 書籍情報の編集画面
- 独自サーバー・データベース

## 4. 画面仕様

### 4.1 ホーム画面

アプリを開いたときに表示するメイン画面。

表示内容：
- アプリ名「100分 de 名著 読書ルーレット」
- 登録書籍数
- 未読数
- 読書中数
- 読了数
- シリーズ別の未読数
- 抽選対象の種類を選ぶフィルター
- ルーレット
- 抽選結果
- 書籍一覧への導線

ルーレットの動作：
1. 抽選対象の種類を決める。初期値は「すべて」。
2. 選択した種類に属する未読書籍だけを抽選候補にする。
3. ルーレットを実行する。
4. 抽選結果として書影、タイトル、シリーズ種別を表示する。
5. 公式商品ページへのリンクと読書状況変更ボタンを表示する。

抽選結果を表示しただけでは、読書状況を変更しない。

未読書籍が0冊の場合はルーレットを無効化し、「抽選対象の未読書籍がありません」と表示する。

### 4.2 書籍一覧画面

カタログに存在するすべての書籍を一覧表示する。

各書籍に表示する情報：
- 書影サムネイル
- 書籍タイトル
- 著者・講師などの情報（取得できる場合）
- 刊行年月または放送年月（取得できる場合）
- シリーズ種別
- 読書状況
- 公式商品ページへのリンク

絞り込み：
- すべて
- テキスト
- ブックス
- 別冊

読書状況の絞り込み：
- すべて
- 未読
- 読書中
- 読了

検索：
- タイトルによる部分一致検索
- 日本語の文字列を入力して検索できること

読書状況は一覧から直接変更できる。書籍情報そのものは利用者が編集できない。

表示順は、原則として刊行・放送年月の新しい順とする。年月が不明な場合は末尾に表示する。

### 4.3 バックアップ画面

利用者が読書記録をバックアップ・復元できるようにする。

機能：
- JSONファイルのダウンロード
- JSONファイルの読み込み
- 読み込み前のデータ検証
- 復元前の確認表示
- 不正なJSONや未知の形式に対するエラー表示

復元時に現在の記録を誤って消さないよう、操作前に明確な確認を行う。

## 5. 読書状況の仕様

読書状況は次の3種類とする。

| 状態 | 意味 | ルーレット対象 |
|---|---|---|
| unread | まだ読んでいない | 対象 |
| reading | 読書中 | 対象外 |
| completed | 読了済み | 対象外 |

初めてカタログに追加された書籍は未読として扱う。

### 5.1 状態変更

- 未読から読書中に変更できる。
- 未読から読了に変更できる。
- 読書中から読了に変更できる。
- 読了から未読・読書中に戻せる。
- 読書中の本は複数冊あってもよい。
- 読書状況の変更は即座に保存する。

読了日はMVPの必須項目にしない。読了済みであることを記録できればよい。

## 6. ルーレットの仕様

### 6.1 抽選対象

以下の条件をすべて満たす書籍のみ抽選対象とする。

- 読書状況が未読である。
- 選択中のシリーズフィルターに一致する。

抽選候補の生成処理と乱数による選択処理をUIコンポーネントから分離する。

### 6.2 抽選結果

- 候補から一冊を均等な確率で選択する。
- 抽選結果の表示だけでは読書状況を変更しない。
- 再抽選できる。
- 読書状況が変更された場合、次回抽選から最新状態を反映する。
- 抽選対象が0冊の場合、例外を発生させず空の結果を返す。

### 6.3 抽選アルゴリズム

概念上は以下の処理とする。

```ts
const candidates = books.filter(
  book =>
    book.status === "unread" &&
    (selectedSeries === "all" ||
      book.series === selectedSeries)
);

if (candidates.length === 0) {
  return null;
}

const index = Math.floor(random() * candidates.length);
return candidates[index];
```

乱数関数はテスト時に差し替えられるようにする。

## 7. データモデル

### 7.1 書籍カタログ

```ts
type SeriesType = "text" | "books" | "special";

interface CatalogBook {
  id: string;
  title: string;
  series: SeriesType;
  author?: string;
  publicationDate?: string;
  broadcastDate?: string;
  isbn?: string;
  thumbnailUrl?: string;
  officialUrl?: string;
}
```

`id` はカタログ更新後も同じ書籍を識別できる安定したIDとする。

優先順位：
1. ISBNなど、安定して取得できる識別子
2. 取得元の商品ID
3. 安定したルールに基づくID

タイトルだけをIDにすると、表記変更や同名書籍によって読書記録が分断されるため避ける。

### 7.2 読書記録

```ts
type ReadingStatus = "unread" | "reading" | "completed";

interface ReadingRecord {
  bookId: string;
  status: ReadingStatus;
  updatedAt: string;
}
```

読書記録はカタログと分離して保存する。

読書状況が未読のものについては、記録が存在しない場合も未読として扱ってよい。

### 7.3 localStorage

キーはバージョン付きとする。

```text
100min-meicho-reading-records-v1
```

カタログJSONは静的アセットとして配信し、localStorageには保存しない。

カタログに存在しないIDの読書記録が残っていても、読み込み時にアプリがクラッシュしないこと。バックアップには、カタログから消えた本の記録も可能な範囲で保持する。

## 8. カタログ取得・更新

### 8.1 取得処理

ビルド前に実行できるNode.jsスクリプトを用意する。

責務：
- データソースから商品情報を取得する。
- テキスト・ブックス・別冊を分類する。
- 必要なフィールドに正規化する。
- 重複書籍を除去する。
- データを検証する。
- `src/data/books.json` などの静的JSONを生成する。
- 取得結果とエラーをログに出力する。

### 8.2 書影

- 書影が取得できる場合はサムネイルを表示する。
- 書影が取得できない場合はプレースホルダーを表示する。
- Amazonの商品画像を無断で取得・保存・再配布しない。
- 画像の利用条件が確認できない場合は利用しない。
- 外部画像の取得失敗で画面全体が壊れないようにする。

書影URLが期限付き・認証必須・外部利用不可の場合は、永続的な画像URLとして使用しない。

### 8.3 取得失敗時

外部サイトの一時障害によって公開ビルドが直ちに失敗しないようにする。

- 生成済みカタログが存在する場合は、明示的な設定に従って前回のデータを利用できるようにする。
- 初回取得でカタログが生成できなかった場合は、原因が分かるエラーを出してビルドを失敗させる。
- データ取得に成功したように見せかけて空のカタログを公開しない。
- 更新前後の書籍数と、シリーズ別の件数を記録する。
- 大幅な件数減少などは警告する。

### 8.4 定期更新

GitHub Actionsで定期更新できる構成にする。ただし、更新頻度は取得元の利用条件を確認して決める。

手動実行によるカタログ更新も可能にする。

カタログ更新によって読書記録が消失しないことを必須要件とする。

## 9. データのマージと重複防止

カタログ更新時は、カタログのIDと読書記録の`bookId`を対応付ける。

- 既存IDの本は読書状況を維持する。
- 新規IDの本は未読として扱う。
- カタログから削除された本の読書記録を即座に破棄しない。
- 同一ISBNなどで同一と判断できる本は重複登録しない。
- 同じ作品のテキストとブックスは、異なる商品であるため原則として別書籍として扱う。

同じ作品を扱うことと、同じ書籍商品であることを区別する。

## 10. バックアップ形式

JSONファイルには形式バージョンと読書記録を含める。

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-10-16T10:00:00.000Z",
  "records": [
    {
      "bookId": "stable-book-id",
      "status": "completed",
      "updatedAt": "2026-10-16T10:00:00.000Z"
    }
  ]
}
```

インポート時の要件：
- JSONとして解析できることを検証する。
- `schemaVersion`を確認する。
- 各レコードの型と状態値を検証する。
- 不正なファイルは読み込まない。
- 読み込み前に現在のデータが置き換わることを説明する。
- 将来の形式変更に備えて、形式バージョンを維持する。

## 13. デザイン方針

- スマートフォンを第一に考える。
- 本の表紙を主役にする。
- 書籍の種類は文字ラベルで明示する。
- 色だけでシリーズを区別しない。
- タイトル・書影・状態が一目で分かるレイアウトにする。
- ルーレットの演出は短く、操作を妨げない。
- アニメーションを減らす設定にも配慮する。
- 書影がない本も同じレイアウトで表示する。
- 画面を開いてから抽選までの操作を少なくする。

シリーズラベル：
- テキスト
- ブックス
- 別冊

日本語UIを標準とする。

## 14. テスト要件

### 14.1 ルーレット

- カタログが空なら`null`を返す。
- 未読書籍が0冊なら`null`を返す。
- 読書中の本は抽選されない。
- 読了済みの本は抽選されない。
- 選択したシリーズ以外の本は抽選されない。
- シリーズが「すべて」の場合は3種類が対象になる。
- 乱数0の場合に先頭候補が選択される。
- 乱数が1未満の範囲で最後の候補も選択できる。
- 抽選によって読書状況が変更されない。

### 14.2 読書記録

- 保存した状態を再読み込み後に復元できる。
- 新しい本を追加しても既存の読書記録が残る。
- 読了から未読に戻せる。
- 不正なlocalStorageデータに対して適切なエラー処理を行う。
- 保存領域が不足した場合にエラーを表示する。
- カタログに存在しないIDがあってもクラッシュしない。

### 14.3 カタログ

- 必須フィールドがないデータを検出する。
- 重複書籍を検出する。
- 3種類のシリーズ分類を検証する。
- 書影がない本を許容する。
- 外部サイトの取得失敗を検出する。
- 取得件数の異常な減少を警告する。

### 14.4 公開

- ローカルの本番ビルドが成功する。
- GitHub Pagesのサブパスで正しく表示される。
- 直接アクセスやページ再読み込みで404にならない。
- スマートフォンの画面幅で操作できる。
- 読書記録がページ再読み込み後も保持される。

## 15. 受け入れ条件

以下をすべて満たした時点でMVP完成とする。

1. テキスト・ブックス・別冊のカタログを扱える。
2. 書籍の種類が一覧・抽選結果の両方で識別できる。
3. 未読の本だけを抽選できる。
4. 読書中・読了の本は抽選されない。
5. 読書状況をブラウザ内に保存できる。
6. 書影がない本も正常に表示される。
7. JSONで読書記録をバックアップ・復元できる。
8. カタログ更新によって既存の読書記録が消えない。
9. GitHub Pagesに自動デプロイできる。
10. テスト・Lint・ビルドが成功する。
11. アフィリエイト機能が含まれていない。
12. データ取得元の利用条件と書影の利用条件が確認されている。

## 16. Copilotへの実装指示

本仕様書に基づき、次の順番で実装する。

### Phase 1：動作する最小構成

- Vite + React + TypeScriptの初期化
- 仮の書籍JSONによる画面実装
- 読書状況管理
- localStorage保存
- ルーレット
- 書籍一覧・検索・フィルター
- 単体テスト

### Phase 2：カタログ取得

- NHK出版公式サイトおよび書誌APIの調査
- 取得元の利用条件の確認
- カタログ取得スクリプトの実装
- 3シリーズの分類
- ID設計と重複除去
- 書影取得・表示
- 取得失敗時の処理

### Phase 3：データ保護と公開

- JSONバックアップ・復元
- GitHub Actions
- GitHub Pagesのパス設定
- モバイル表示の確認
- READMEと運用手順の整備

実装中は、未確認のAPI仕様や取得件数を推測で埋めないこと。外部サイトの構造や規約に依存する部分は、調査結果と制約をREADMEに記録すること。

各Phaseの終了時にテスト・Lint・ビルドを実行し、失敗を残したまま次のPhaseへ進まないこと。

まずPhase 1を完成させ、その後Phase 2のデータ取得方式を確定する。
